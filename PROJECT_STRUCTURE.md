# Mutator Project - Complete Structure & Flow

## Project Overview

This is a **Kubernetes mutating webhook operator** built with Kubebuilder. Its primary purpose is to intercept and modify Pod creation/update requests in a Kubernetes cluster.

---

## Purpose

The mutator acts as a **Pod defaulting webhook** that automatically modifies Pod specifications before they are persisted in etcd. Specifically:

- **Intercepts Pod requests**: When Pods are created or updated
- **Mutates Pod specs**: Changes the `ServiceAccountName` field
- **Default behavior**: If a Pod has no service account or uses the default one, it replaces it with `"No-Access"` (a restricted service account)

This is a security control mechanism to prevent Pods from using the unrestricted default service account.

## Complete Project Structure & Flow

### 1. Entry Point: `cmd/main.go`

- Initializes the Kubernetes manager (controller-runtime)
- Registers the webhook server on the manager
- Configures TLS certificates for secure webhook communication
- Sets up metrics and health probes
- Runs the manager in a continuous loop

**Key responsibilities:**
- Parse command-line flags (metrics address, webhook cert paths, TLS options)
- Set up logging with zap logger
- Configure webhook server with TLS certificates
- Configure metrics server with security filters
- Create and start the manager

### 2. Webhook Implementation: `internal/webhook/v1/pod_webhook.go`

The core logic that performs the actual mutation:

```
Kubernetes API Server
        ↓ (Pod create/update request)
Webhook Interceptor (MutatingWebhookConfiguration)
        ↓
PodCustomDefaulter.Default() method
        ↓ (Mutates ServiceAccountName)
Pod stored in etcd
```

**What happens:**
1. User creates a Pod (e.g., `kubectl apply -f pod.yaml`)
2. Kubernetes API server sends an `AdmissionReview` to the webhook endpoint
3. The webhook's `Default()` method runs:
   - If `spec.serviceAccountName` is empty or "default" → change it to "No-Access"
   - Otherwise, leave it unchanged
4. Returns the mutated Pod spec to the API server
5. API server persists the modified Pod

**Webhook Marker:**
```go
// +kubebuilder:webhook:path=/mutate-core-v1-pod,mutating=true,failurePolicy=fail,...
```

This tells Kubebuilder to:
- Create a webhook at path `/mutate-core-v1-pod`
- It's a mutating webhook (not validating)
- Fail the request if the webhook fails
- Watch core/v1 Pod resources on create and update operations

```

│   ├── manager_webhook_patch.yaml # Enables webhook in manager

│
```

**Key files explained:**

- **`config/webhook/manifests.yaml`** - Defines `MutatingWebhookConfiguration` that tells the API server:
  - Which webhook endpoint to call
  - Which resources to intercept (Pods)
  - Which operations to intercept (create, update)
  - How to authenticate with the webhook

- **`config/rbac/role.yaml`** - Generated from `+kubebuilder:rbac:` markers in source code:
  - Defines minimum permissions needed
  - Auto-generated by `make manifests`

- **`config/manager/manager.yaml`** - Kubernetes Deployment spec:
  - Container image
  - Port configuration (webhook, metrics, health probe)
  - Certificate volume mounts
  - Resource limits
  - Security context

## Deployment & Execution Flow

### Local Development

```bash
# 1. Set up local Kind cluster
kind create cluster

# 2. Install cert-manager (required for webhooks)
kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.19.2/cert-manager.yaml

# 3. Run webhook locally
make run

# 4. Test by creating Pods
kubectl apply -f config/samples/
```

### Kubernetes Deployment

```bash
# 1. Regenerate manifests
make manifests generate

# 2. Build and push container
export IMG=<registry>/<project>:tag
make docker-build docker-push IMG=$IMG

# 3. Deploy to cluster
make deploy IMG=$IMG

# 4. Verify deployment
kubectl get deployment -n mutator-system
kubectl get mutatingwebhookconfigurations

# 5. Test the webhook
kubectl run test-pod --image=nginx
kubectl get pod test-pod -o yaml | grep serviceAccountName
# Output: serviceAccountName: No-Access
```

**Deployment sequence:**
1. cert-manager creates TLS certificates for the webhook
2. Manager pod starts, initializes the webhook server
3. Webhook registers itself with the Kubernetes API server
4. When a Pod is created/updated, API server calls the webhook via HTTPS
5. Webhook mutates the Pod spec and returns it
6. Metrics exposed on `:8080` for Prometheus scraping
7. Health probes available on `:8081`

## Security Model

### TLS/HTTPS
- Webhook communication is encrypted
- Certificates issued by cert-manager
- Certificates auto-rotate

### Authentication
- Managed by Kubernetes Service Account
- Service Account token mounted in webhook Pod
- Mutually authenticated (API server verifies webhook cert, webhook verifies API server cert)

### Authorization (RBAC)
The webhook Pod has minimal permissions:
- Read pods (to verify mutations)
- Read secrets (for cert-manager certificates)
- Create events (for logging)

**Defined in:** `config/rbac/role.yaml` (auto-generated from `+kubebuilder:rbac:` markers)

### Failure Policy
- If the webhook fails: `failurePolicy: fail`
- The Pod creation/update request is **rejected**
- Ensures security policy is always enforced (fail-safe)

## Lifecycle Events

### Pod Creation with Webhook

```
1. User runs: kubectl run test --image=nginx

2. Request reaches API server

3. API server checks MutatingWebhookConfigurations
   ↓
   Finds: "Intercept core/v1 Pod on create"

4. API server sends AdmissionReview to webhook:
   POST https://webhook-service.mutator-system:443/mutate-core-v1-pod
   {
     "apiVersion": "admission.k8s.io/v1",
     "kind": "AdmissionReview",
     "request": {
       "operation": "CREATE",
       "object": {
         "apiVersion": "v1",
         "kind": "Pod",
         "metadata": {"name": "test"},
         "spec": {
           "containers": [{"name": "nginx", "image": "nginx"}]
           // serviceAccountName is EMPTY
         }
       }
     }
   }

5. Webhook processes request:
   - Calls PodCustomDefaulter.Default()
   - Detects: spec.serviceAccountName is empty
   - Mutates to: "No-Access"
   - Returns AdmissionResponse

6. API server receives response:
   {
     "apiVersion": "admission.k8s.io/v1",
     "kind": "AdmissionReview",
     "response": {
       "allowed": true,
       "patch": "[{"op":"add","path":"/spec/serviceAccountName","value":"No-Access"}]",
       "patchType": "JSONPatch"
     }
   }

7. API server applies patch and stores Pod:
   spec:
     serviceAccountName: No-Access  // ← MUTATED!
     containers:
     - image: nginx
       name: nginx

8. Pod is created and scheduled normally
```
